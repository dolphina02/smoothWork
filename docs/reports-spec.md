# Reports 화면 기능명세

## 1. 목적

확정된 `tasks`/`dependencies`(+ Board의 리스크 판정, 마일스톤 휴리스틱)를 바탕으로
팀용/임원용 리포트를 자동 생성하고, 사람이 다듬어서 링크/PDF로 공유한다.
과거 리포트는 히스토리로 남는다.

## 2. 스키마 갭 — 사전 결정 사항

현재 스키마에는 리포트를 저장할 테이블이 없다. 다음 테이블을 추가한다.

```sql
CREATE TABLE reports (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  type TEXT CHECK (type IN ('team','executive')),
  period_start DATE,
  period_end DATE,
  title TEXT,
  sections JSONB,              -- [{key, label, content_md, ai_generated, edited}, ...]
  status TEXT DEFAULT 'draft' CHECK (status IN ('draft','shared')),
  share_token TEXT,            -- 공유 전에는 null
  share_expires_at TIMESTAMPTZ,
  source_snapshot JSONB,       -- 생성 시점에 사용된 task/dependency id 스냅샷 (재현/추적용)
  created_at TIMESTAMPTZ DEFAULT now(),
  shared_at TIMESTAMPTZ
);
```

추가로 Board 스펙(10.1절)에서 이미 제안한 `tasks.completed_at`이 리포트의 "이번 기간
완료된 태스크" 집계에 그대로 필요하다 — 별도 갭이 아니라 기존 제안을 재사용한다.

## 3. 레이아웃

```
┌───────────────────┬──────────────────────────────────────────┐
│ 좌측: 리포트 히스토리 │ 우측: 에디터 / 프리뷰                       │
│ [+ 새 리포트]        │                                            │
│                     │  [헤더: 제목, 기간, 상태뱃지]                │
│ ○ 8/4 팀 주간 리포트 │  [탭: 편집 / 미리보기]                      │
│ ○ 7/28 임원 요약     │  [섹션별 편집 카드 목록]                     │
│ ● 7/21 팀 주간(공유됨)│  [하단: 공유 링크 생성 / PDF 내보내기]        │
│ ...                 │                                            │
└───────────────────┴──────────────────────────────────────────┘
```

- 좌측: 히스토리 리스트 (Inbox의 리스트-상세 패턴 재사용). 각 항목: 유형 아이콘,
  기간, 생성일, 상태 뱃지(초안/공유됨)
- 우측: 선택된 리포트의 에디터. 상단 탭으로 "편집"/"미리보기" 전환

## 4. 새 리포트 생성

"+ 새 리포트" 클릭 → 생성 폼(모달, Inbox의 반려 사유 모달과 동일 톤):
- **유형**: 팀용(상세) / 임원용(요약)
- **기간**: 지난 1주 / 지난 2주 / 커스텀 날짜 범위
- **담당자 범위**: 전체 / 특정 담당자만 (다중 선택)

"생성" 클릭 → 로딩 상태(섹션별 스켈레톤) → 섹션이 순서대로 채워지며 초안 완성.
생성 직후 자동으로 "편집" 탭이 열린다.

### 4.1 팀용(상세) 리포트 섹션 구성
1. **기간 요약** — 한두 문장 하이라이트
2. **완료된 태스크** — 담당자별로 묶어서 나열 (`completed_at`이 기간 내인 태스크)
3. **진행중 & 예정 마감** — 기간 내 `due_date`가 있는 미완료 태스크
4. **리스크 / 블로커** — Board 5절 기준 리스크 있는 dependency, 지연 태스크(overdue) 나열
5. **다음 기간 계획** — 다음 기간에 마감이 몰린 태스크 미리보기

### 4.2 임원용(요약) 리포트 섹션 구성
1. **헤드라인** — 전체 상태 한 줄 (on-track / at-risk / delayed 뱃지 + 한 문장)
2. **핵심 성과** — 3~5개 불릿
3. **주요 리스크** — 마일스톤 휴리스틱(Board 3절)에 걸리는 항목 중심, 실무 디테일 생략
4. **필요한 의사결정** — 반려/수정 사유가 반복되는 패턴이 있으면 LLM이 제안 (있을 때만 표시,
   없으면 섹션 자체를 숨김)

## 5. 편집

- 각 섹션은 카드 형태. 카드 상단에 "AI 생성" 배지 — 사람이 내용을 고치면 Inbox와 동일한
  패턴으로 "편집됨" 배지로 전환 (`sections[].edited` 플래그)
- 텍스트는 간단한 서식(굵게/목록)만 지원하는 경량 리치텍스트, 마크다운 소스와 1:1 대응
- 카드마다 **"이 섹션만 다시 생성"** 버튼 — 편집한 내용은 버리고 해당 섹션만 LLM 재호출.
  편집된 상태에서 누르면 "편집 내용을 덮어씁니다" 확인 필요
- 섹션 순서 변경/삭제는 v1 범위 밖 (섹션 구성은 유형별로 고정)

## 6. 미리보기

- "미리보기" 탭 = 실제로 공유됐을 때 보이는 최종 렌더링 (편집 UI 없이 클린한 문서 형태)
- 팀용/임원용에 따라 문서 스타일 차등 (임원용은 더 큰 타이포, 여백 넉넉하게 — 스캔하기 쉬운 톤)

## 7. 공유

- **링크 생성**: 만료 기간 선택(7일/30일/무제한) → `share_token` 발급, 읽기 전용 URL 복사.
  공유 시점에 `status`가 `shared`로 바뀌고, 이후 편집해도 이미 발급된 링크의 스냅샷은 안 바뀐다
  (링크는 발급 시점 `source_snapshot` 기준 고정 — 최신 데이터 반영은 "새 리포트 생성"으로 유도)
- **PDF 내보내기**: 미리보기 렌더링을 그대로 PDF로 다운로드 (v1: 브라우저 인쇄 다이얼로그 활용
  수준으로 충분, 별도 PDF 렌더러 도입은 backlog)
- 공유 후에도 편집은 계속 가능하지만, 편집하면 "공유된 링크와 내용이 달라졌습니다 — 다시
  공유하시겠어요?" 배너를 상단에 표시

## 8. 히스토리

- 리스트는 `created_at` 내림차순
- 리포트 클릭 → 우측에 로드, 상태가 `shared`인 리포트는 기본적으로 "미리보기" 탭으로 열림
  (이미 나간 리포트를 실수로 편집하지 않도록), `draft`는 "편집" 탭으로 열림
- 리포트 우클릭/케밥 메뉴: 복제해서 새 초안 만들기 / 삭제

## 9. 엣지 케이스

- 해당 기간에 완료/진행중 태스크가 전혀 없음 → 그 섹션은 "이번 기간엔 해당 없음" 문구로 채움
  (섹션 자체를 숨기지 않음 — 팀용 리포트는 "아무 일도 없었다"는 사실도 정보이기 때문)
- 담당자 범위를 좁혔는데 리스크/블로커가 범위 밖 담당자에게 있는 경우 → "범위 밖 태스크가
  이 담당자의 일정에 영향을 줄 수 있음" 각주로 표시 (Board 임팩트 분석과 동일한 관점)
- 생성 중 LLM 실패 → 실패한 섹션만 재시도 버튼과 함께 에러 상태로 표시, 나머지 섹션은 정상 노출
- 공유 링크 만료 후 접근 → 별도 뷰어(로그인 없는 외부 열람용, v1 범위 밖 상세 설계)에서
  "만료된 링크입니다" 안내만 정의

## 10. v1 범위 밖 (backlog)

- 섹션 순서 변경/커스텀 섹션 추가
- 전용 PDF 렌더러 (현재는 브라우저 인쇄로 대체)
- 외부 열람용 공유 링크 뷰어의 상세 UX
- 리포트에 차트/그래프 삽입
