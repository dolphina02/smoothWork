# Today 화면 기능명세

## 1. 목적

"오늘 뭘 해야 하는가"를 한 화면에서 처리한다. 두 가지를 세로로 합친다.

- **오늘 할 일**: 확정된 태스크 중 오늘 마감이거나 진행 중인 것들의 to-do list
- **검토 대기**: 아직 확정되지 않은 태스크 후보(`extracted_candidates`)의 triage 큐 — 기존
  Inbox 화면(inbox-spec.md)을 그대로 흡수한 것

앱 셸(app-shell-spec.md 3절)의 **기본 진입 화면**이다 — "오늘 뭘 해야 하는지"가 앱을 열었을 때
가장 먼저 봐야 할 정보라는 전제.

## 2. 레이아웃

```
┌──────────────────────────────────────────────────────────────────┐
│ 오늘 할 일                                        [3 / 7 완료]      │
│ ────────────────────────────────────────────────────────────────│
│ ⚠ 지연됨 (2)                                                       │
│  ☐ 결제 모듈 리팩토링 (8/10 마감 · 최민준)                            │
│ 오늘 마감 · 진행중 (5)                                              │
│  ☑ 인증 서버 스펙 검토 (김도현)                                      │
│  ☐ 리포트 자동 배포 (8/12 마감 · 이은지)                             │
│  ...                                                                │
├──────────────────────────────────────────────────────────────────┤
│ 검토 대기                                          [4 pending]      │
│ ────────────────────────────────────────────────────────────────│
│ ┌───────────────┬────────────────────────────────────────────┐  │
│ │ 필터바          │  [원본 발화 뷰어]                              │  │
│ │ 후보 카드 리스트  │  [추정 필드 편집 폼]                           │  │
│ │ (Inbox 3절)    │  [액션 바: 승인 / 수정 후 승인 / 반려]           │  │
│ └───────────────┴────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────────┘
```

- 위아래 두 영역은 각자 독립적으로 스크롤한다 — "오늘 할 일"은 화면 상단에 자연 높이로,
  "검토 대기"가 나머지 공간을 채운다 (Inbox의 2단 리스트-상세 레이아웃 그대로)
- 두 영역 사이 비율을 사용자가 드래그로 조정하는 기능은 9절 backlog

## 3. 오늘 할 일 (To-do List)

### 3.1 대상 태스크

`tasks` 중 다음 조건을 만족하는 것:

- `due_date <= 오늘` AND `status != 'done'` — 이 중 `due_date < 오늘`인 것은 **"지연됨"** 그룹으로
  상단에 별도 강조 표시 (Board 4절의 "지연" 배지와 동일한 판정 기준)
- 또는 `status = 'in_progress'` (마감일이 오늘이 아니어도 지금 진행 중이면 포함)

담당자 필터는 두지 않는다 — 개인용 도구 전제(다른 스펙 문서들과 동일)라 기본적으로 모든 태스크를
"내 할 일"로 간주한다.

### 3.2 항목 구성 & 완료 처리

- 체크박스, 제목, 담당자, `due_date`
- 체크박스 클릭 → `status='done'`, `completed_at` 자동 기록 (Board 10.1절에서 정의한 필드를
  그대로 재사용 — 이 화면이 그 자동 기록 트리거 지점 중 하나가 된다)
- 항목 본문 클릭(체크박스 제외) → Task 화면(task-spec.md)의 해당 보드로 이동, 그 태스크가
  선택된 상태로 열린다 — 상세 편집/의존관계 확인은 Task 화면에서 한다 (이 화면은 완료 체크만
  담당)

### 3.3 엣지 케이스

- 오늘 할 일이 0건이면 "오늘 마감/진행중인 태스크가 없습니다" 안내
- 담당자 미배정 태스크도 기본적으로 포함한다 (전부 "내 것"으로 간주하는 개인용 도구 전제)

## 4. 검토 대기 (Inbox 흡수)

- inbox-spec.md 2~6절을 그대로 적용한다 — 리스트-상세 패턴, confidence 점, 필터/정렬, 원본
  발화 뷰어, 추정 필드 편집 폼, 액션 바(승인/수정 후 승인/반려), 키보드 단축키(J/K/A/E/R/Esc)
  전부 동일
- 차이점은 범위뿐이다 — 이 화면은 날짜 무관하게 **전체 pending 후보**를 다룬다. Yesterday의
  Follow-up Task 탭(digest-spec.md 7절)은 이 중 "특정 날짜에서 나온 것만" 보여주는 부분집합이다
- "N pending" 카운터도 Inbox와 동일하게 유지한다

## 5. Yesterday의 Follow-up Task와의 관계

- 이 섹션과 Yesterday의 Follow-up Task 탭은 같은 `extracted_candidates` 데이터, 같은 승인/반려
  API를 공유한다 — 한쪽에서 처리한 항목은 다른 쪽에서도 즉시 사라진다 (digest-spec.md 7.4절과
  상호 참조, 별도 동기화 로직 불필요)

## 6. 엣지 케이스

- **오늘 할 일 + 검토 대기 둘 다 비어있음**: "오늘은 할 일도, 검토할 것도 없습니다 🎉" 통합 안내
  (Inbox Zero 문구의 확장판)
- **한쪽만 비어있음**: 있는 섹션은 정상 표시하고, 빈 섹션만 축소된 안내 문구로 대체 (예: 검토
  대기가 0건이면 그 영역에 "Inbox Zero 🎉"만 작게 표시)

## 7. v1 범위 밖 (backlog)

- 두 섹션 높이/비율을 사용자가 드래그로 조정
- to-do 항목의 수동 우선순위 정렬
- 반복 태스크(recurring task)
