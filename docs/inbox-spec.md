# Inbox 화면 기능명세

## 1. 목적

`extracted_candidates` 중 `status='pending'`인 항목을 사람이 빠르게 검토(triage)하여
승인/수정/반려하는 화면. Slack이나 이메일의 "Inbox Zero" 워크플로처럼, 카드 단위로
빠르게 훑고 다음 카드로 넘어가는 리듬을 최우선으로 설계한다.

## 2. 레이아웃

```
┌───────────────────┬──────────────────────────────────────────┐
│ 좌측: 후보 리스트   │ 우측: 상세/검토 패널                        │
│ (240–320px)        │                                            │
│                     │  [원본 발화 뷰어]                          │
│ ● 필터/정렬 바      │  [추정 필드 편집 폼]                        │
│ ○ 후보 카드 #1      │  [액션 바: 승인 / 수정 후 승인 / 반려]      │
│ ○ 후보 카드 #2      │                                            │
│ ● 후보 카드 #3 (선택)│                                            │
│ ...                 │                                            │
└───────────────────┴──────────────────────────────────────────┘
```

- 2단 레이아웃. 리스트-상세 패턴 (Gmail/Superhuman 유사).
- 리스트에서 카드를 선택하면 우측 패널이 즉시 갱신된다 (라우팅 없이 SPA 내 상태 전환).
- 화면 하단 또는 상단에 "12 pending · 3 today reviewed" 같은 진행 카운터 표시.

## 3. 좌측: 후보 리스트

### 3.1 카드 구성 요소
각 카드는 다음을 표시한다:
- **Confidence 점**: 색상 원 (초록 ≥0.8 / 노랑 0.5–0.79 / 빨강 <0.5). 색만으로 구분하지
  않도록 카드 hover/상세에서 숫자값(`0.72`)도 함께 노출한다 (접근성).
- **출처 아이콘**: Slack / WAV / MP3 (source 필드 기준)
- **추정 태스크 제목** (`suggested_task`) — 1줄 truncate
- **추정 담당자** (`suggested_assignee`) — 없으면 "담당자 미정" 회색 텍스트
- **발생 시각** (`meetings.occurred_at`) — 상대시간 표기 ("2시간 전", "어제")
- **원본 스니펫 미리보기** (`raw_text_snippet`) — 2줄 truncate, 회색 보조 텍스트

### 3.2 정렬/필터
- 기본 정렬: `created_at` 내림차순 (최신 우선)
- 필터: 전체 / confidence 낮음(<0.5) 우선 / 출처별(Slack/WAV/MP3) / 회의별
- "confidence 낮음 우선" 필터는 검토자가 놓치기 쉬운 애매한 항목을 먼저 처리하도록 유도

### 3.3 리스트 상태
- **선택됨**: 좌측 강조 바 + 배경색 변경
- **처리 완료(이번 세션)**: 체크마크 오버레이 + 리스트에서 서서히 제거(fade-out, 300ms)
- **빈 상태**: pending 후보가 0개면 "Inbox Zero 🎉" 일러스트 + 메시지, 상세 패널은 안내 문구로 대체

## 4. 우측: 상세/검토 패널

### 4.1 원본 발화 뷰어 (상단)
- **Slack 소스**: 메시지 버블 형태로 원문 렌더링. 화자명 + 채널명 표시. 링크는 실제 클릭 가능.
- **오디오 소스(WAV/MP3)**: 웨이브폼 시각화 + 재생 버튼 + `timestamp_sec` 위치에 마커.
  마커 클릭 시 해당 지점부터 재생. 화자 라벨(diarization) 표시.
- 두 경우 모두 스니펫 앞뒤 문맥(전/후 2턴)을 "더보기"로 펼쳐볼 수 있게 한다 —
  추출 근거를 검토자가 판단하려면 스니펫만으로는 부족한 경우가 많기 때문.

### 4.2 추정 필드 편집 폼
| 필드 | 입력 방식 | 비고 |
|---|---|---|
| 태스크 제목 | 텍스트 인풋 | `suggested_task` 기본값 |
| 담당자 | 오토컴플리트 (기존 인물 목록) | `suggested_assignee` 기본값, 목록에 없으면 자유 입력 허용 |
| 기한 | 날짜 피커 | `suggested_due` 기본값, 비어있을 수 있음 |
| 의존관계 | 타입(blocks/blocked_by) + 대상 태스크 검색 | `suggested_dependency` 기본값. 대상이 기존 `tasks`와 매칭 안 되면 "미확정 참조" 칩으로 표시하고 자유 텍스트 유지 |
| Confidence | 읽기 전용 배지 | 편집 불가, 참고용 |

- 필드를 원본 제안값에서 변경하면 해당 필드 라벨 옆에 "수정됨" 뱃지 표시 (dirty state 추적)
- 변경 여부는 승인 액션이 "승인"인지 "수정 후 승인"인지를 자동으로 결정한다
  (하나라도 dirty하면 액션 버튼 라벨이 "수정 후 승인"으로 자동 전환)

### 4.3 액션 바
세 가지 액션, 각각 `human_review_log`에 기록:

1. **승인** — 필드 변경 없이 그대로 확정. `tasks`/`dependencies`에 즉시 반영.
   사유 입력 불필요.
2. **수정 후 승인** — 하나 이상 필드가 dirty할 때 활성화되는 버튼 라벨.
   **사유 입력 필수** (드롭다운 프리셋 + 자유 텍스트):
   - 프리셋 예: "담당자 재배정", "기한 정정", "의존관계 추가/수정", "제목 명확화", "기타"
3. **반려** — 후보를 폐기. **사유 입력 필수**:
   - 프리셋 예: "중복", "태스크 아님(잡담)", "오인식(STT/LLM 오류)", "관련 없음", "기타"

- 모든 액션은 `original_suggestion`(변경 전 JSON), `final_decision`(변경 후 JSON 또는 null),
  `reasoning`(텍스트)을 `human_review_log`에 저장한다.
- 액션 완료 즉시 좌측 리스트에서 해당 카드가 fade-out되고, **다음 pending 카드가 자동 선택**된다
  (문서 4.1절의 "triage 리듬" 요구사항).

### 4.4 키보드 단축키 (triage 속도를 위해)
| 키 | 동작 |
|---|---|
| `J` / `↓` | 다음 카드 |
| `K` / `↑` | 이전 카드 |
| `A` | 승인 |
| `E` | 편집 모드로 포커스 이동 (첫 필드) |
| `R` | 반려 (사유 입력 모달 오픈) |
| `Esc` | 편집 취소 / 모달 닫기 |

## 5. 상태 및 엣지 케이스

- **저장 실패/네트워크 오류**: 액션 버튼에 인라인 에러 표시, 카드는 리스트에서 제거하지 않음(재시도 가능)
- **중복 후보 감지**: `suggested_task`가 기존 `tasks`와 유사도 높으면 (Board/RAG 검색 활용)
  상세 패널 상단에 "유사 태스크 발견" 경고 배너 + 링크. 검토자가 병합/무시 선택 가능
  (v1에서는 배너만 표시, 자동 병합은 범위 밖)
- **의존관계 대상 미존재**: `suggested_dependency.target_task_id`가 없고 `target_text`만 있는 경우,
  "이 태스크가 아직 후보 상태일 수 있음" 안내 + 나중에 자동 매칭되도록 텍스트 보존
- **오디오 로딩 실패**: 웨이브폼 대신 재생 불가 안내, 텍스트 스니펫만으로 검토 진행 가능해야 함
- **연속 반려 경고**: 동일 세션에서 반려율이 비정상적으로 높으면(예: 연속 5개) 배치 반려 여부를
  확인하는 것이 향후 개선 후보 (v1 범위 밖, 메모만 남김)

## 6. 데이터 매핑 요약

- 리스트/폼 초기값: `extracted_candidates.*`
- 승인/수정 확정 시: `tasks` insert/update, `dependencies` insert (있는 경우)
- 모든 액션: `human_review_log` insert (`action` = confirmed / modified / rejected / reassigned / date_changed 중 해당 필드 변경에 맞는 값. 여러 필드가 동시에 바뀌면 `modified`로 통합하고 `final_decision`에 세부 diff 기록)

## 7. v1 범위 밖 (backlog)

- 배치 승인/반려 (여러 카드 다중 선택)
- 자동 병합 (중복 후보)
- 담당자 워크로드 기반 추천
