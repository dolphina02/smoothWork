# 앱 셸(App Shell) 기능명세

## 1. 목적

지금까지 따로 존재하던 화면들을 하나의 앱으로 묶는 전역 레이아웃. Teams류 도구처럼 **좌측 아이콘
사이드바로 화면을 전환**하고, **우측 LLM 채팅 패널은 화면 전환과 무관하게 항상 고정**된다.
이 문서는 셸 자체(사이드바, 채팅 패널, 화면 전환 방식)만 다루고, 각 화면의 내부 동작은 개별
스펙 문서를 따른다.

이 스펙 이후로 "Digest"는 사이드바 라벨 **Yesterday**로, "Inbox"는 **Today** 안으로 흡수된다.
Reports는 이번 개편 범위 밖이며 별도로 다시 논의한다.

## 2. 레이아웃

```
┌────┬──────────────────────────────────────────────┬───────────────┐
│ ▤  │                                                │  LLM 채팅      │
│Yes │                                                │  ─────────    │
│ □  │                                                │  [메시지 히스토리]│
│Tdy │              선택된 화면 컨텐츠                    │               │
│ ▦  │        (Yesterday/Today/Task/Meeting/          │               │
│Tsk │              Configuration)                    │               │
│ ▥  │                                                │               │
│Mtg │                                                │  ─────────    │
│ ⚙  │                                                │  [입력창]      │
│Cfg │                                                │  [전송]        │
└────┴──────────────────────────────────────────────┴───────────────┘
  56px                     가변                            320px
```

- **좌측 아이콘 사이드바** (고정 폭 56px, hover 시 라벨 툴팁): 아이콘 5개, 세로 배치
- **중앙 컨텐츠 영역**: 선택된 화면이 렌더링되는 자리. 화면 전환은 라우팅 없이 SPA 내 상태
  전환(Inbox 3절과 동일 전제)
- **우측 LLM 채팅 패널** (고정 폭 320px, 접기/펼치기 가능): 어떤 화면을 보고 있든 항상 같은
  자리에 유지된다 — 화면 전환 시 채팅 컴포넌트는 unmount되지 않고, 대화 스크롤 위치와 세션
  상태를 그대로 유지한다

## 3. 사이드바 항목

| 아이콘 라벨 | 화면 문서 | 대체하는 기존 개념 |
|---|---|---|
| **Yesterday** | `digest-spec.md` (Digest, 개편) | 기존 Digest — 미팅/Slack/Follow-up Task 3개 탭으로 재구성 |
| **Today** | `today-spec.md` (신규) | to-do list + 기존 Inbox의 후보 검토(triage) 흡수 |
| **Task** | `task-spec.md` (신규, `board-spec.md` 래핑) | 기존 Board — 보드(프로젝트)가 여러 개일 수 있어 스위처 추가 |
| **Meeting** | `meeting-list-spec.md` (신규) | 어제 하루가 아니라 동기화된 Outlook 일정 전체를 훑어보는 화면 |
| **Configuration** | `configuration-spec.md` (신규) | Outlook 연동 / LLM 설정 / Slack 채널 관리 — 그동안 여러 문서에서 "별도 설정 화면 필요"로 미뤄둔 것들을 통합 |

기본 진입 화면은 **Today**로 한다 — "오늘 뭘 해야 하는가"가 앱을 열었을 때 가장 먼저 봐야 할
정보라는 전제 (4절 today-spec.md와 일치).

## 4. 우측 LLM 채팅 패널

### 4.1 v1 범위
- 텍스트 입력 + 메시지 히스토리만 지원하는 단순 채팅 UI
- 백엔드는 `mcp-tool-spec.md`의 툴들을 호출해 저장된 데이터(미팅/Slack 요약, 태스크, 리포트)를
  조회하고 답변에 활용할 수 있다 — 다만 **읽기 전용** 원칙(mcp-tool-spec.md 2절)은 이 채팅에도
  그대로 적용된다. 채팅으로 태스크를 승인/생성/수정하는 기능은 만들지 않는다 (Today/Yesterday의
  액션 UI를 우회하지 않기 위함)
- 현재 보고 있는 화면(예: Today 화면이면 오늘 to-do 목록)을 채팅 컨텍스트에 자동으로 포함할지는
  9절 backlog — v1은 사용자가 직접 질문에 맥락을 적어 넣는 것을 전제로 한다

### 4.2 상태 유지
- 채팅 세션은 앱 셸 레벨 상태로 관리되어, 좌측 사이드바로 화면을 전환해도 유지된다
- 브라우저 새로고침 시 세션 유지 여부는 9절 backlog (v1은 새로고침하면 초기화되어도 무방)

### 4.3 접기/펼치기
- 패널 상단에 접기 버튼 — 접으면 중앙 컨텐츠 영역이 그만큼 넓어짐 (폭 0으로, 얇은 아이콘 탭만
  남겨 다시 펼 수 있게)

## 5. 화면 전환 규칙

- 사이드바 아이콘 클릭 시 즉시 전환 (탭처럼, 확인 모달 없음)
- 화면을 나갈 때 저장되지 않은 편집 중 상태가 있어도(예: Today의 to-do 체크, Yesterday의 요약
  편집) 경고 없이 전환한다 — 각 화면의 편집은 필드 단위로 즉시 저장되는 것을 전제로 하며(Reports/
  Digest 스펙의 기존 패턴과 동일), "저장 안 된 변경사항" 개념 자체가 없다

## 6. 반응형/최소 너비

- v1은 데스크톱 전용 폭을 전제로 한다 (사이드바 56px + 채팅 320px를 제외한 중앙 영역이 각 화면의
  최소 요구 폭을 만족해야 함 — 예: Task의 타임라인, Yesterday의 리스트-상세 2단 레이아웃)
- 모바일/좁은 화면 대응은 9절 backlog

## 7. v1 범위 밖 (backlog)

- 사이드바 항목 커스터마이즈/재배열
- 채팅 히스토리 영구 저장, 여러 대화 세션 관리
- 채팅에 현재 화면 컨텍스트 자동 주입
- 다크/라이트 테마 전환
- 모바일/반응형 레이아웃
- Reports 화면을 이 IA에 어떻게 재배치할지 (이번 개편 범위 밖, 별도 논의 필요)
